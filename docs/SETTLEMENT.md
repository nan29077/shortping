# 정산 · 세무 · 방송국 설계

2026-09-19 기준. 로컬 개발 버전의 구현 범위이며, 실제 결제·지급대행 연동 전 단계입니다.

## 방송국 (마이 방송국)

PD 한 명당 방송국 한 개를 운영합니다. 몰인몰 구조처럼 방송국이 자신의 숏폼 드라마를 모아 보여주는 독립 페이지를 가집니다.

- 구성: 이름, 주소(slug), 한 줄 소개, 소개글, 배너, 로고, 대표 색상, 공개 상태(준비 중 · 공개 · 숨김).
- 카테고리(진열대)는 방송국당 최대 12개. 작품을 카테고리에 배치하며, 공개 중인 작품도 진열은 변경할 수 있습니다. 진열은 노출 순서만 바꾸므로 심사 상태에 영향을 주지 않습니다.
- 작품을 새로 등록하면 해당 PD의 방송국에 자동으로 소속됩니다.
- 시청자는 방송국을 구독(팔로우)할 수 있고, 메인 화면과 마이페이지에서 구독 중인 방송국의 작품을 모아 봅니다.
- 관리자는 방송국별 공개 상태와 메인 추천 노출·순서를 관리합니다. 추천으로 지정된 방송국이 메인 "지금 주목할 방송국"과 방송국 목록 상단에 표시됩니다.
- 공개(active) 상태의 방송국만 목록과 상세에 노출되며, 준비 중·숨김 상태는 운영자와 소유 PD만 열람합니다.

## 정산 원장

주문이 생성되는 트랜잭션 안에서 정산 항목을 함께 기록합니다. 매출과 정산이 어긋날 수 없는 구조입니다.

| 상태 | 의미 |
| ---- | ---- |
| `pending` | 판매 확정 대기. 구매일 + 판매 확정일(기본 7일)이 지나면 자동 전환 |
| `available` | 출금 가능 |
| `requested` | 출금 신청으로 잠김 |
| `paid` | 지급 완료 |

- 정산액 = 판매액 − 플랫폼 수수료(기본 30%) − 결제 수수료(기본 0%, PG 연동 후 사용). 금액은 정수 원 단위로만 저장합니다.
- 수수료율을 변경해도 이미 생성된 항목은 당시 요율(`fee_rate`)을 유지합니다.
- 숏핑 패스(구독) 매출은 개별 작품에 귀속되지 않으므로 월 마감 시 배분합니다. 해당 월 구독 매출 총액을, 같은 기간 시청 기록의 회차 비중으로 PD별로 나눕니다. 같은 달을 다시 마감해도 결정적 ID(`sub-YYYY-MM-<pd>`)로 중복 생성되지 않습니다.
- 진행 중인 달은 마감할 수 없습니다.

## 출금

1. PD가 세무 정보와 출금 계좌를 등록합니다.
2. 출금 가능 금액 전액을 한 번에 신청합니다(최소 출금 금액 기본 10,000원). 신청 시 해당 정산 항목이 `requested`로 잠깁니다.
3. 관리자가 승인 → 지급 완료로 처리하거나, 사유를 적어 반려합니다. 반려하면 정산 항목이 `available`로 복구됩니다.
4. 지급대행을 붙이면 3단계의 승인·지급을 대행사 API 호출로 교체합니다. 현재는 관리자 수동 처리이며 실제 이체는 일어나지 않습니다.

## 세무 처리

| 구분 | 처리 |
| ---- | ---- |
| 사업자 | 세금계산서 발행 대상. 정산 기준액(공급가)에 부가세 10%를 더해 지급 |
| 비사업자 | 사업소득 3.3%(소득세 3% + 지방소득세 0.3%) 원천징수 후 지급 |

- 사업자는 사업자등록번호 10자리, 상호, 대표자명을 필수로 입력합니다. 업태·종목·세금계산서 이메일·사업장 주소는 선택입니다.
- 관리자는 세무 구분을 직접 지정하고 검증 완료로 표시할 수 있습니다. PD가 정보를 수정하면 검증 상태는 다시 대기로 돌아갑니다.
- 주민등록번호 등 민감 식별정보는 저장하지 않습니다. 원천징수 신고와 지급명세서 제출에 필요한 정보는 지급대행 연동 단계에서 수집합니다.
- 관리자 세무 관리 화면에서 연도별 지급액·부가세·원천징수액을 집계하고 CSV로 내려받을 수 있습니다.

## 운영 설정

슈퍼관리자가 요금 · 정책 설정에서 바꾸는 값은 `platform_settings` 테이블에 저장되고 결제·정산 경로가 즉시 참조합니다.

`subscription_price`, `subscription_days`, `default_drama_price`, `default_free_episodes`, `platform_fee_rate`, `pg_fee_rate`, `settle_hold_days`, `payout_min`, `withholding_rate`, `vat_rate`, `payout_notice`

- 구독료와 이용 기간은 결제 시점의 설정값으로 계산합니다. 클라이언트가 보낸 금액은 사용하지 않습니다.
- 작품 판매 설정에서 공개 중인 작품의 소장 가격, 무료 회차, 뱃지, 노출 상태(공개 · 노출 중단)를 조정합니다. 가격을 0원으로 두면 전 회차가 무료로 공개되며, 이미 구매한 시청자의 권한은 유지됩니다.

## 회원 관리

- 전체 / 시청자 / PD · 방송국 / 관리자 / 이용 제한 · 탈퇴 탭으로 나누어 조회합니다.
- 목록에서 결제 건수·금액, 소장·찜·시청 수, PD의 작품 수와 정산 잔액, 방송국 이름을 함께 표시합니다.
- 회원별 관리 메뉴: 상세 정보, 회원 정보 수정(이름·연락처·권한·이용 상태), 방송국 보기, 세션 종료, 메일 보내기.
- 상세 정보에는 결제·시청·소장·문의·작품·방송국·정산·출금 이력과 운영 메모가 모입니다.
- 이용 제한 또는 탈퇴로 바꾸면 모든 로그인 세션이 즉시 종료되고, 변경 이력은 운영 기록에 남습니다. 구매 내역과 정산 기록은 보존합니다.

## 데이터

`platform_settings`, `channels`, `channel_categories`, `channel_follows`, `pd_tax_profiles`, `payouts`, `settlement_entries`, `member_notes` 테이블을 추가했고 `dramas`에 `channel_id`, `category_id`, `published_at`, `users`에 `last_login_at`, `phone` 컬럼을 더했습니다. 컬럼 추가는 SQLite와 PostgreSQL 모두에서 기존 데이터베이스를 유지한 채 서버 시작 시 적용됩니다.

## 후속 범위

실제 PG·지급대행 연동, 환불·부분 취소에 따른 정산 차감, 부분 금액 출금, 구독 자동 갱신, 세금계산서 자동 발행과 원천징수 신고, 지급명세서 제출, 정산 알림(메일·알림톡)은 다음 단계입니다. 현재 구현은 테스트 결제를 기준으로 한 정산 흐름 검증용입니다.
