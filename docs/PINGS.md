# 핑(포인트) 시스템

회차·작품 결제를 원화 직접 결제에서 **핑 충전 → 핑으로 열기**로 바꿨습니다. 숏핑 패스(구독)는 원화 그대로입니다.

## 기본 규칙

| 항목 | 기본값 | 바꾸는 곳 |
| ---- | ---- | ---- |
| 1핑 기준가 | 100원 (10,000원 = 100핑) | 포인트(핑) 관리 › 가격 정책 |
| 기본 회차 가격 | 5핑 | 가격 정책 (작품별 값은 작품 판매 설정 / PD 작품 편집) |
| 작품 전체 열기 할인 | 20% | 가격 정책 |
| 충전 상품·보너스 구간 | 5천/1만/3만(+15)/5만(+40)/10만(+100) | 충전 상품 (웹 · App Store · Google Play 별도) |
| PD : 플랫폼 | 70 : 30 | 가격 정책(공통), 분배 비율(PD별) |
| 결제 채널 수수료 | 웹 PG 0% · App Store 30% · Google Play 30% | 가격 정책 |

- 작품 전체 열기 = 남은 잠긴 회차 수 × 회차 핑 × (100 − 할인율)% 올림. 한 편 가격보다 싸지지 않고, 1편만 남으면 할인하지 않습니다.
- 보너스(무상) 핑을 먼저, 오래된 충전분부터 씁니다.
- 자동 열기(`auto_unlock`)를 켜면 잠긴 회차에 들어갈 때 확인 없이 보유 핑으로 엽니다. 켜는 순간 보고 있던 회차는 열지 않고, 핑이 부족하면 열지 않습니다.

## 정산 — 인앱 수수료가 있어도 7:3이 지켜지는 방식

충전 한 번이 하나의 **로트**가 되고, 로트마다 "유료 핑 1개가 실제로 번 순매출"을 기록합니다.

```
1핑 순매출 = 결제액 × (100 − 채널 수수료%) ÷ 유료 핑 수
```

회차를 열면 쓰인 핑의 순매출 합계가 판매액(gross)이 되고, 이것을 PD 몫과 플랫폼 몫으로 나눕니다. 채널 수수료는 충전 시점에 이미 빠졌으므로 PD:플랫폼 비율은 채널과 관계없이 정확히 유지됩니다.

| 10,000원 충전 → 5핑 회차 1편 | 채널 수수료 | 판매액 | 플랫폼 30% | PD 70% |
| ---- | ---- | ---- | ---- | ---- |
| 웹 결제 | 0원 | 500원 | 150원 | 350원 |
| App Store (30%) | 3,000원 | 350원 | 105원 | 245원 |
| App Store 14,300원 상품 | 4,290원 | 500원 | 150원 | 350원 |

- 인앱 가격을 수수료만큼 올려 두면(10,000 ÷ 0.7 ≈ 14,300원) PD 정산이 웹과 같아집니다. 실제 가격은 스토어 가격 등급에 맞춰야 합니다.
- 같은 충전의 **보너스 핑**도 같은 단가로 PD에게 정산됩니다. 보너스 비용은 플랫폼이 마케팅비로 부담합니다.
- **관리자 지급 핑**은 기준가(1핑 = `ping_unit_won`)로 정산됩니다. 회수는 정산을 만들지 않습니다.
- 가격·요율을 바꿔도 이미 충전된 핑의 단가와 이미 기록된 정산은 바뀌지 않습니다.

## 데이터

| 테이블 | 역할 |
| ---- | ---- |
| `ping_products` | 충전 상품 (채널·가격·핑·보너스·뱃지·판매 여부) |
| `ping_wallets` | 회원별 잔액 캐시 (충전 핑 · 보너스 핑, 음수 불가) |
| `ping_lots` | 충전·지급 단위 로트와 1핑 순매출(`unit_milli`, 원×1000) |
| `ping_ledger` | 충전·사용·지급·회수 장부 (변동 후 잔액, 사용 가치) |
| `ping_consumptions` | 사용·회수가 어느 로트에서 몇 핑을 썼는지 |
| `pd_settlement_rates` | PD별 플랫폼 몫(없으면 공통 비율) |

주문(`orders`)에는 `ping_charge`(원화 결제), `ping_episode`·`ping_title`(금액 0, `pings`에 사용 핑)이 남습니다. 모든 변경은 한 트랜잭션에서 처리하고, PostgreSQL에서는 지갑 행을 잠급니다.

## API

- 시청자: `GET /api/pings`, `POST /api/pings/charge`, `POST /api/pings/unlock`, `PUT /api/account/auto-unlock`
- 관리자: `GET /api/admin/pings`, `POST|PATCH|DELETE /api/admin/pings/products`, `POST /api/admin/pings/adjust`, `PUT /api/admin/pings/rates/:id`
- 핑 부족 오류는 `code: "insufficient_pings"`, `need`, `balance`를 함께 돌려주고, 화면은 충전 화면(`#/pings/<돌아올 주소>`)으로 안내합니다.

## 남은 연동 작업

1. **PG 연동**: `POST /api/pings/charge`를 "결제 승인 확인(웹훅·서버 검증) → `creditPings`"로 바꿉니다. 적립 로직은 그대로 씁니다. 실제 PG 요율을 `pg_fee_rate`에 넣습니다.
2. **인앱결제(App Store · Google Play)**: 앱 출시 전에 스토어 상품 ID 연결, 영수증 서버 검증, 환불(취소) 통지 처리 → 로트 회수가 필요합니다. 스토어 정책상 앱 안의 디지털 상품은 인앱결제를 써야 하므로 앱 심사 전 반드시 연동해야 합니다.
3. **환불 정책**: 미사용 충전 핑 환불 규정과 처리(해당 로트 회수)를 정해야 합니다.
